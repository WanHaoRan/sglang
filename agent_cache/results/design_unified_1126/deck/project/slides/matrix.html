Here is the whole design on one slide; the following slides take it action by action. Four actions decide every movement of KV, on every tier. Fetch decides when a copy moves up: when a read from the SSD starts and in which order the device serves reads, and whether a missing history is read or recomputed. Retain decides which copies each tier keeps: which sessions stay in GPU and host memory, when a page is written to the SSD, which is keeping a copy one tier down, and what the SSD’s cleaner deletes. Preempt decides who gives way when a resource is full right now: which holder of host memory yields to an arriving read, whether a write or a read goes first on the device, and on the GPU, that a turn whose read has not landed is passed over. Price says what one more unit of each resource costs, in seconds of TTFT: mu for a GPU-second, lambda for a host token-second, kappa for a device-second, and the weight c of a second of stall. Three ideas hold it together. One clock: every transfer has a due time derived from T, the arrival plus the queue wait. Three prices: the queue at each resource sets what one more unit costs. And one comparison per action: given the prices, each session’s best move is a short formula, and it is provably the best move in the priced problem. The paper’s four actions covered reads and host eviction with the queue taken as fixed. Here the same four also cover the queue wait, the shape of the hint, the write, and the SSD’s own eviction.
