One H200, Qwen3-30B-A3B, 16-bit KV: 98,304 bytes a token, 6 MiB a 64-token page. Measured in campaign 34 (128 users, 160 GB host pool, FlashAttention 3).

The prefix cache can be in three places. GPU memory holds 668 thousand tokens of KV, enough for about 20 turns running at once. Host memory holds 1.63 million tokens in a 160 gigabyte pool; the engine keeps a host copy of every page the GPU holds, so 0.65 million of those tokens mirror the GPU and 0.97 million are left for sessions that are not on the GPU. The SSD holds about 25 million tokens, but it is one device that moves 2.1 gigabytes a second, reads and writes together, which is 21 thousand tokens a second: less than one average session a second. Where a session’s KV is decides what its next turn pays. On the GPU, nothing. In host memory, a copy that takes under a tenth of a second. On the SSD, a read into host memory and then the copy: about 1.1 seconds on an idle device, after waiting its place in the device’s line, and late in a busy run that wait reaches 40 seconds. If the KV is nowhere, the GPU recomputes it: about 0.8 seconds for 25 thousand tokens on an idle GPU, and on a busy GPU every turn waiting behind it waits as well. With 128 sessions in progress the KV adds up to about 320 gigabytes, and memory holds half of it. So KV has to move between tiers all the time, and the questions are when, which, and in what order.
