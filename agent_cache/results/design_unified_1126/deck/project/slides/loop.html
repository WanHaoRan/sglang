Turn

One request to the model. The agent sends the whole conversation again, 25.5K tokens on average, of which 1.1K are new (what the tool returned), and the model writes about 280 tokens.

Gap

The pause before the session’s next request. After nine turns in ten the agent runs a tool: half are back within 1.0 s, one in ten takes over 8 s. After the others a person answers: half take over 68 s, one in ten over 12 minutes.

Prefix cache (KV)

The model’s attention state for the tokens it has already read: 98 KB a token, 2.5 GB for an average session. With it a turn computes only its new tokens; without it, the whole prompt again.

Workload: FreeInference, recorded coding-agent sessions replayed at their recorded pace. Model: Qwen3-30B-A3B on one H200. Gap figures: the sessions as replayed (103K gaps).

Start with what is being served. An agent session is a loop. A turn is one request to the model: the agent framework sends the whole conversation so far, the model replies, and the reply usually asks for a tool call, such as running a test or reading a file. While the tool runs, the session is idle; we call that pause a gap. Then the next turn arrives with everything the previous one had plus the tool’s output. In the workload used here, recorded coding-agent sessions from the FreeInference trace, a request carries 25.5 thousand tokens on average and only 1.1 thousand of them are new. Most gaps are tool calls and short, half of them under one second, but one in ten takes over 8 seconds, and when a person has to answer, half of the gaps exceed 68 seconds and one in ten exceeds twelve minutes. The serving engine keeps the model’s attention state for the tokens already read, the prefix cache or KV cache, so that a turn computes only its new tokens. That state is large: 98 kilobytes a token, about 2.5 gigabytes for an average session.
