The four actions · Fetch, part 2

Fetch before arrival: the hint’s shape decides

Start the read s seconds from now if the turn is not back by then. The queue hides W of the read’s r seconds, so x = r − W of it can show.

J(s) = c · x − c · M(s) + (c + λL) · M(s + x)

dJ / ds = P(not back by s) · (c + λL) · (F(x | s) − q)

Waiting a second longer saves rent if the turn is still far off and costs stall if it arrives within x. The sign turns on whether F(x | s) is above q.

Measured

On this trace the return rate falls beyond 2 s for 94 % of requests, and a timed start adds 0.000 to 0.002 s per returning request. Where gaps are sharp (another trace, gaps stretched ten times), exact hints took 0.15 to 0.22 s of a 0.23 to 0.29 s ceiling.

Sharp hint: F(x | s) rises as the session stays idle

Start the first time F(x | s) ≥ q. Best at every price exactly when F(x | s) never falls.

Heavy-tailed hint: it falls

The best start is an end point: now or at arrival. A copy Retain let go is not worth reading back at the same prices; Fetch then only repairs a forced eviction.

The queue caps what any hint can buy

A read before arrival saves at most c · (r − W)⁺ per return: nothing once the queue wait exceeds the read time.

M(t) = E[(R − t)⁺], R the time left until the return · F(x | s): chance of return within x of s, given not back by s · q = λL / (c + λL) · the copy is held from landing to admission

Now the harder case: the session is still away and its history is on the SSD. Should the read start before the request arrives, and when? Suppose the read starts s seconds from now if the turn is not back by then, and otherwise at its arrival. The queue hides W of the read’s r seconds, so only x, r minus W, can show as stall. The priced cost has a closed form: c times x, minus c times M of s, plus c plus lambda L times M of s plus x, where M of t is the expected time the session is still away beyond t. Its derivative is the chance of not being back by s, times c plus lambda L, times F of x given s minus q. In words: waiting one more second saves rent if the turn is still far off, and costs stall if it arrives within x; the sign turns on whether the chance of return within x has reached q. So the shape of the hint decides. With a sharp hint, the chance of return within x rises as the session stays idle: start the read the first time it reaches q. That threshold is the best rule at every price exactly when this chance never falls. With a heavy-tailed hint it falls: the cost is lowest at an end point, start now or wait for the arrival, and there is a sharper statement, that a copy which Retain let go is never worth reading back at the same prices. On such a hint, Fetch before arrival only repairs a forced eviction, when a price fell or the copy was pushed out. And in every case the queue caps what a hint can buy: a read before arrival saves at most c times the positive part of r minus W per return, nothing once the queue wait exceeds the read time. Measured, on this trace the return rate falls beyond two seconds for 94 percent of requests, and a timed start adds between zero and two thousandths of a second per returning request. On another trace with sharp gaps, exact hints took 0.15 to 0.22 seconds of a ceiling of 0.23 to 0.29.
