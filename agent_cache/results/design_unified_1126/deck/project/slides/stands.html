128 users, 160 GB host pool, 2 h, FlashAttention 3; mean TTFT of requests sent in the first 110 minutes. Left: campaign 30, paired with the current design. Right: campaign 34.

Before the design, where things stand. On this workload, with 128 users for two hours, the current design was compared with six other systems on the same requests. Each of them makes a request wait 25 to 66 seconds longer for its first token, on average, than the current design does. The three that keep history only in GPU memory wait about 65 seconds longer; the ones that also use host memory, 25 to 55. So tiering the prefix cache with hints is already worth a great deal. But look at our own designs on the right, in the same setting. With exact knowledge of every gap, the best one reaches 10.66 seconds. The current design, which uses the realistic hint table, is at 10.96. Just-in-time reads are at 10.92 with exact hints and 11.47 on the median. Only stock HiCache, at 31.88, is far away. Once the GPU is saturated, the designs that protect queued turns sit within one second of each other, whatever they do with the hint. A model of this system has to explain that tie, and then say where a gain is still to be had: in which regimes, and from which decisions. That is what the rest of the deck does.
