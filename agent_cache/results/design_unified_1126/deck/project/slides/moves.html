Five kinds of movement keep the tiers in step. A load copies KV from host memory to the GPU when a turn is taken; it costs under a tenth of a second of that turn’s own time. A backup copies new KV from the GPU to host memory. A write copies it from host memory to the SSD. A read brings it back from the SSD into host memory. And a recompute rebuilds KV from the tokens on the GPU when no copy is at hand. Each movement has a moment by which it is needed: a load and a read by the moment the GPU would take the turn, a backup by the moment the GPU gives the page up, and a write by the moment host memory gives the page up. And each uses shared resources. GPU time is one queue of turns, so work added for one turn delays every turn behind it. Host memory is a fixed number of tokens, so room kept for one session is room that another cannot use. SSD time is one device with one line, so a read and a write cannot both go first. A cache policy is the set of decisions about these movements: when each read starts and in which order the SSD serves them, which copies each tier keeps, what is written and when, and who gives way when a resource is full. In the engine today a different mechanism makes each of these decisions, each with its own constants. The design in this deck makes all of them with four actions and one set of prices.
